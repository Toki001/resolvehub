# Milestone 08 — operational telemetry and measured load

Verified locally on 2026-10-21 with Node 22.22.3, pnpm 12.10.1, macOS arm64 and Docker Desktop. This records executed local checks. No remote Actions run, image push or production deployment is claimed.

## Delivered

- Shared `packages/telemetry` with early API/worker initialization, ESM dependency hooks, Next.js instrumentation, strict environment validation, bounded asynchronous OTLP traces/metrics and shutdown. Official PostgreSQL/ioredis instrumentation runs beneath explicit HTTP, GraphQL, durable queue, ingestion and RAG spans.
- Transactional allowlisted trace metadata on job receipts, tenant-scoped reloads, BullMQ producer/consumer propagation, compatibility with empty legacy context, and an additive migration with a restricted global numeric queue aggregate. Replay remains authorized independently of trace context.
- SDK privacy processors reconstruct spans before buffering and filter metric names, keys and enum values. Raw customer text, tenant/resource IDs, credentials, SQL, Redis arguments, provider payloads, events/links, exception messages, baggage/tracestate and automatic process/host resources are excluded. Diagnostics do not log exporter payloads. New tests use actual SDKs and a compiled instrumented API.
- Request percentiles, GraphQL errors, queue depth/age/wait, retry/dead-letter events and durable counts, successful ingestion throughput, retrieval/generation timing, token counts, known cost and incomplete-usage signals. Global queue gauges use max across replicas. Event counters can undercount a commit followed by a crash; SQL state remains authoritative.
- Independent pinned local Collector/Tempo/Prometheus/Grafana Compose project, 17 provisioned panels, 11 alerts, two alert-firing fixtures, loopback ports and a generated private Grafana credential. CI validates Collector/Prometheus configuration and dashboard provisioning files. Production deployment examples accept optional OTEL settings.
- Checksum-pinned native k6 runner and isolated synthetic ten-VU drafting/1005-request saturation harness. It verifies real Tempo operations, dependency instrumentation, canary redaction and current-worker Prometheus export. New development/Make commands, recovery/rollback documentation, architecture decision and measured performance report accompany the implementation.

## Failures and corrections

- SDK 3.x uses `@opentelemetry/sdk-trace` and revised processor constructor options; an initial old package/API combination was corrected to the matching pinned set. ESM hooks were necessary for actual dependency spans.
- Initial instrument creation before SDK registration produced noop metrics. Lazy instrument creation fixed this; tests now use a real meter provider and the benchmark asserts the current worker's exported queue gauge. A one-second metric interval initially conflicted with the export timeout; timeout validation now follows the configured interval.
- Privacy review caught object-spreading SDK spans retaining private internal fields. Exported spans now reconstruct only public safe fields before buffering. Metric descriptions/units, unknown metric names and extra datapoint fields are also removed.
- Initial ESM integration tests needed an explicit Jest import. A read-only promtool container needed a bounded writable `/tmp` for rule-test storage. Strict lint caught a list used only as a type; the same list now drives the runtime metric allowlist.
- Exploratory k6 runs caught too-short idempotency keys and an unrelated-title quality failure: only **2/30** expected-answer/evidence checks passed with a generic ticket subject. The final benchmark uses canonical question subjects without changing AI behavior. This limitation is retained in the [performance report](../performance-report.md).
- A local Next.js development type-generation race required a typecheck rerun. A tool approval review temporarily hit a usage cap and did not execute a read; after the user resumed, the same authorized read succeeded. Neither changed application behavior.

## Handoff and limits

See [operations and recovery](../operations/observability.md), [decision 0009](../architecture/decisions/0009-private-operational-telemetry.md), [performance report](../performance-report.md) and [curated measured JSON](milestone-08-metrics.json). Full generated reports/logs remain ignored under `test-results/` and `coverage/`. Local observability is available on loopback; existing development infrastructure and data volumes were preserved. Enable `OTEL_ENABLED=true` and restart the development applications to export their telemetry.

The benchmark uses free synthetic embeddings and extractive mock generation, a small corpus and a short 30-draft burst. It does not establish remote-provider quality/cost/latency, sustained ingestion capacity, telemetry overhead, production ingress behavior, production paging or high availability. Prometheus evaluates local alerts, but Alertmanager notification routing is not configured. Finite telemetry buffers can drop data during outages. Production TLS/access control, retention, paging and remote CI execution require deployment configuration. Application limitations from milestone 06 remain, including incomplete dashboard data/auth wiring and deferred outbound customer messaging; human approval remains mandatory.
