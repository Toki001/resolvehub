## Root cause found and confidence limits

The installed official `@google/genai` **2.30.0** implementation's `getHeadersInternal` appends `X-Server-Timeout: ceil(httpOptions.timeout / 1000)` (installed `dist/node/index.mjs`, lines 13905–13908). ResolveHub passed its **5,000 ms local timeout** into that SDK field, also instructing the service to use a **five-second server deadline**. The historical minimal success used 10,000 ms. An original [provider rejection report and maintainer discussion](https://github.com/livekit/agents/issues/3723) records HTTP 400 for a manually set five-second deadline below the ten-second minimum.

The fix separates these concerns: SDK server deadline `max(10000, localTimeoutMs)`, independent local AbortSignal and full-pipeline time bounds retained. The official SDK still performs exactly one HTTP attempt, with continuation disabled. The regression fixture returns 400 for the old five-second header and succeeds through the actual SDK/worker with ten seconds; another check proves a 100 ms local abort remains effective against an uncooperative transport.

This establishes a concrete request-configuration defect and a reproducible repair. **It does not prove the discarded bodies of all three historical failures had this exclusive cause**, or that the current cloud endpoint will accept a full cited response. Milestone 10 also measured unsupported structured-format configurations; those optional fields remain absent. Standard text carries a versioned strict JSON prompt, then runtime schema and exact retrieved-evidence validation. No new unverified schema/parameter guess was sent to Google. Final live acceptance is still required.

The workflow smoke now requires `GEMINI_MAX_ATTEMPTS=1`; the operator must restart its worker with that value before invoking it.

### Error/privacy review

Fixed stages are `source`, `retrieval`, `context`, `generation`, `response_parsing`, `citation_validation`, `persistence`, `complete`. Categories distinguish provider unavailable, model/request configuration, application/provider quota, retrieval/context failure, invalid response, invalid citations, persistence, timeout and unexpected worker execution. Invalid content safely abstains; invalid provider metadata or dependencies fail explicitly. HTTP 404/400/429 never automatically retry. SDK has `attempts: 1`; worker attempts default 2 for Gemini, configurable down to 1, with Retry-After and finite cooldown. Application quota and model failure state remain shared across replicas and persist across restarts/replays.

The only new application-log fields are fixed event/stage/category/outcome, bounded attempt values and sanitized operational request/job/trace IDs. Correlation comes from validated database state / W3C trace context, not customer text. Null trace IDs explicitly mean tracing supplied none. No new span attributes or metric labels were added; tenant/resource IDs, text, SQL, raw errors, credentials and provider payloads are excluded. A failed logging sink cannot retry a committed draft. Checkpoint database failure stays a persistence error without falsely poisoning provider health.
