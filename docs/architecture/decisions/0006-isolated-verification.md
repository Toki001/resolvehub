# 0006 — Isolated verification and critical-service coverage

Date: 2026-10-21. Status: accepted for milestone 05.

The previous integration command depended on the developer's database and running API/worker. The verification command now owns ephemeral PostgreSQL 17/pgvector, Redis 7.4 and MinIO containers, random host ports, synthetic credentials, migrations and a compiled worker. PostgreSQL/Redis images use the same digest pins as Compose. MinIO uses the existing release-pinned source Dockerfile, built automatically if its local image is missing. No host data volumes are mounted and `.env` is never loaded.

HTTP suites instantiate the actual `AppModule` using `Test.createTestingModule`, override only validated configuration, and use the same extracted HTTP configuration as production. Guards, controllers, resolvers, repositories and exception handling remain real. Each API instance waits for readiness and closes through Nest's lifecycle. The worker health process remains separate; the ingestion processor and runtime also execute in Jest against real infrastructure. See [Nest testing utilities](https://docs.nestjs.com/fundamentals/testing).

NestJS 12 is ESM. Jest uses `--experimental-vm-modules`, ts-jest's ESM output and explicit `@jest/globals` imports. Contract file resolution uses `createRequire(import.meta.url).resolve`, which works in both Node and Jest's ESM context. See [Jest ESM guidance](https://jestjs.io/docs/ecmascript-modules). Node's experimental warning is expected.

V8 coverage includes API auth/application policy, worker ingestion, scoped persistence/transactions, ticket status policy and AI adapters. Each area has an independent 80% branch threshold. Untouched UI, generated code, environment parsing and process entrypoints outside these areas are outside the coverage claim. The included PDF thread entrypoint reports zero in Jest because it runs in a separate worker thread; real PDF extraction is checked against both compiled and development entrypoints. Its zero remains in the worker area's denominator. Coverage does not imply semantic AI correctness or delivery guarantees.

Testcontainers' Ryuk helper is disabled because the local registry could not serve its helper image during milestone 04. The runner and Redis failure suite explicitly stop their containers; the runner handles normal completion, errors and SIGINT/SIGTERM. SIGKILL or daemon failure can still leave disposable containers for operator cleanup. PostgreSQL schemas/roles, S3 buckets/objects, BullMQ connections and Nest applications have explicit teardown.

Provider failures are injected through the typed embedding boundary using safe HTTP status metadata. No live embedding adapter is enabled and no paid LLM calls run. Production code changes are limited to reusable policy/configuration seams and safe provider failure classification. The ticket state policy supplies ticket creation's initial state; external status commands and rendered evidence-backed drafts remain later product work. Citation units enforce canonical document/version/chunk UUID formatting; integration tests check publication eligibility and rejection of stale or foreign evidence.
