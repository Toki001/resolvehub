# Durable contract APIs and authenticated organization context

Date: 2026-10-20. Scope: milestone 02.

Working contract handlers need persistence for credentials, ticket creation, receipts, accepted asynchronous requests and audited review. The shared database package therefore gains the minimum numbered SQL migrations and scoped repositories needed for those operations. These migrations run explicitly with `pnpm db:migrate`, never on API startup. The runner serializes concurrent runs, records checksums, rejects edits to applied SQL, and applies outstanding changes transactionally. The full Drizzle domain schema, application runtime roles/RLS, seed corpus, migration evolution suite and index publication API remain in milestone 03.

Opaque bearer credentials are generated by a trusted offline provisioning command. Only SHA-256 digests are stored. Every request joins an unexpired, unrevoked credential to its active organization membership; roles and organization context are derived from that join. There is no public sign-up endpoint, trusted tenant header, or development authentication bypass. Analysts may read; agents/admins may command; only admins may replay failures. Browser sign-in/session UI remains future work.

Webhook integration IDs identify server-side organization records. Signing secrets are encrypted at rest with AES-256-GCM under an integration-bound key derived from `API_SECRET_KEY`; signatures authenticate the timestamp and exact raw bytes. Timestamp tolerance is five minutes. Event receipt idempotency is scoped to the integration and organization.

Idempotency keys, payload fingerprints, original receipts, domain writes and audit entries share one PostgreSQL transaction. A unique insert and row lock serialize duplicates across API instances. Keys are retained at least 24 hours; no automatic pruning is installed yet. Review locks the draft and active citation rows. Replay preserves the failed source and permits one new child request per failed job, even if different retry keys are used.

Asynchronous endpoints record **accepted** requests in `job_runs`, a durable handoff boundary for subsequent workers. They do not pretend to enqueue or complete indexing/generation through the operational BullMQ probe. No domain processor or outbound reply delivery is enabled here. Indexing and durable application DLQ remain milestone 04; grounded generation remains milestone 06.

GraphQL uses the planned schema-first Nest Apollo adapter on Express 5. The SDL is loaded directly from `packages/contracts/schema.graphql`; REST request validation uses the canonical OpenAPI JSON Schemas through AJV 2020. Generated client types do not define a second contract. All root queries require the same verified membership as REST. Introspection and request batching are disabled, and a variable-aware cost/depth budget bounds list expansion. Knowledge search currently performs literal text matching over active published chunks; vector retrieval is reserved for the AI milestone.

Every tenant repository query includes organization scope; composite foreign keys prevent cross-organization relationships. This is application/query-level isolation, not a claim of production RLS or a least-privilege deployment. The existing Compose owner role remains a local development role pending the data milestone.
