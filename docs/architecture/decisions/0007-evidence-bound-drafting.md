# 0007 — Evidence-bound asynchronous support drafting

Date: 2026-10-21. Status: accepted for milestone 06.

Drafting is a ticket command, not a chat endpoint. The authenticated API persists a tenant-scoped idempotent request and requester membership. A separate BullMQ consumer reloads the job, ticket and current membership. PostgreSQL advisory locks, four-attempt durable history, a source-job unique key, transactional publication/audit and the application DLQ protect duplicate delivery, interruption and replay. Queue concurrency and provider rate limits are bounded independently from document ingestion.

`packages/ai` depends only on injected provider/retrieval interfaces. The worker supplies `KnowledgeRepository`. Query embedding uses the configured, migration-pinned 64-dimensional synthetic model; changing it requires an explicit migration/reindex. Tenant/live/published/version predicates apply before pgvector cosine ranking and before the full-text candidate channel. Hybrid candidate fusion and optional lexical reranking make this existing synthetic profile useful without claiming semantic embedding quality. The evaluator reports hybrid Recall@5 and the raw synthetic vector baseline separately. Exact candidate loading is suitable for the measured small corpus; these results establish no large-tenant retrieval SLA. See [pgvector operators](https://github.com/pgvector/pgvector#querying).

The pipeline treats tickets and source JSON as untrusted data, rejects recognizable instruction attempts, and requires all significant question terms in selected evidence. This lexical condition is deliberately conservative and cannot prove semantic sufficiency. Provider output must follow a runtime-validated schema. Every accepted factual claim is an exact contiguous source quotation with an allowlisted immutable chunk ID. The server reconstructs document/version IDs and numbered references. Invented IDs, paraphrases, duplicate references and unsupported quotations cause abstention. This provides mechanically checkable quotation support; arbitrary prose entailment, conflicting-policy reasoning and multilingual semantic recall are not claimed. Source and ticket instructions never become tools or authority.

The default extractive mock reads only the supplied question/evidence and never imports golden cases or expected IDs. The optional Ollama adapter posts bounded structured output requests with temperature zero, validates the returned model and usage, limits streamed response bytes, disallows redirects and propagates cancellation. Models are operator-selected; none are downloaded or invoked automatically. The adapter follows [Ollama generate](https://docs.ollama.com/api/generate) and [structured outputs](https://docs.ollama.com/capabilities/structured-outputs). No OpenAI or other paid endpoint is called by normal verification.

A versioned prompt, model/provider identifiers, labelled token estimates or reported usage, explicit per-million-token price assumptions/date, cost and stage timings accompany generated drafts. Prompt selection uses a conservative UTF-8-byte budget, plus a bounded output-token request. Before retrying, the worker subtracts known prior attempt costs from the $0.02 budget. Usage is persisted outside the publication transaction so a publication rollback cannot erase known provider usage. Metadata sums known token/cost observations and flags attempts with unknown usage. Timeout/transport failures may still incur unreported provider charges; estimates are not invoices or a guarantee of total spend. A manual replay is a new explicitly requested draft with its own budget.

Publication rechecks current authority through a narrow SECURITY DEFINER row-lock function instead of granting workers membership/organization writes. Its fixed search path and tenant setting constrain scope; execution is revoked from PUBLIC. Source rows are share-locked through publication. Approval rechecks source version/quotation eligibility and locks source rows. Generated drafts are always pending, abstentions cannot be approved, and no outbound transport or automatic customer reply is introduced.

Migrations 0008–0010 are expand-only. Legacy drafts have null generation metadata and historical idempotency receipts remain valid. New replies expose additive optional REST generation metadata and nullable GraphQL metadata, with required contents when present. Existing migration checksums are untouched. CI runs the 60-case evaluator and independent critical-area coverage gates against isolated real infrastructure; performance and cost reports state provider mode, corpus digest and denominators.
